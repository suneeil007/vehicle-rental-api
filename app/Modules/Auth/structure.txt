Laravel middleware makes this straightforward.

Then create a custom middleware:

role:admin

role:customer

role:driver

role:staff

Example:

    'auth:sanctum',
    'role:admin'
])->group(function () {

    Route::apiResource('vehicles', VehicleController::class);

Development Order

I recommend building the Auth module in this sequence:

Install and configure Sanctum.
Update the users table (add role and status).
Create the Auth module structure.
Build the repository.
Build the service.
Implement Register.
Implement Login.
Implement Logout.
Implement Profile.
Implement Update Profile.
Implement Change Password.
Add role middleware.
Protect the Vehicle, Branch, Booking, and other modules with auth:sanctum.

This gives you a solid authentication foundation before you move on to the remaining business modules like Branch, Booking, Payment, and Review.


For your project (Vehicle Rental API with Laravel 13 + Sanctum + Modular Architecture), I recommend the following best practice.

Your current approach:

app/
└── Modules/
    ├── Vehicle/
    ├── Auth/
    ├── Branch/
    ├── Booking/
    └── ...

is good. Keep it.

But for database migrations, I would slightly adjust the approach.

Recommended Migration Strategy
1. Keep Laravel core tables in default migrations

Do not move these into modules:

database/
└── migrations/

    create_users_table.php
    create_cache_table.php
    create_jobs_table.php
    create_personal_access_tokens_table.php

Reason:

These are framework-level tables, not business modules.

Example:

users
personal_access_tokens
password_reset_tokens

belong to Laravel/Sanctum.

2. Module-specific tables stay inside modules

Example:

app/
└── Modules/

    ├── Vehicle/
    │   └── Database/
    │       └── Migrations/
    │           ├── create_vehicle_categories_table.php
    │           ├── create_vehicles_table.php
    │           └── create_vehicle_images_table.php


    ├── Branch/
    │   └── Database/
    │       └── Migrations/
    │           └── create_branches_table.php


    ├── Booking/
    │   └── Database/
    │       └── Migrations/
    │           └── create_bookings_table.php


    └── Auth/
        └── Database/
            └── Migrations/
                └── create_roles_table.php

This is what you already started with Vehicle. Continue the same pattern.
